# Manual Shelf · 静态说明书资料库

把一个说明书目录转换成可公开托管的静态网站。**无需数据库、账号、MCP、API 或常驻应用进程**。正文直接写入 HTML，访问者与可浏览网页的 Agent 都能循链接读取；浏览器内搜索不需要后端。

## 先打开网站

**不用先运行任何命令。** 仓库已经包含可直接打开的 `site/index.html`：这是网站，不是安装向导。空站首页说明用途、资料目录与更新方法；`site/` 也可以直接部署到静态托管。

### 放入自己的说明书

每本说明书一个文件夹，放在 `site.json` 里的 `manuals_dir`（默认 `manuals/`）下；其下可放 PDF、文字文件、扫描照片，照片依文件名**自然排序**并作为同一本说明书的连续页面。例如：

```text
manuals/
  厨房/
    某品牌/
      型号-123/
        原厂说明书.pdf
        manual.json            # 可选：保存确认的设备信息
  清洁/
    另一品牌/
      型号-456/
        001.jpg
        002.jpg
```

- 未提供 `manual.json` 时，说明书只取**文件夹名**作为标题，品牌 / 型号留空，类别记为「未分类」。不靠目录层级猜测品牌型号，避免误判。
- 子目录递归识别，每一层文件夹都是一本独立说明书；顶层散文件每篇各自成一本。
- 多个 PDF 或 PDF 与照片混合时，构建会**明确告警**并按文件名自然排序拼接，不会静默合并；请核对页序与是否缺页。

运行时只需：

```text
python3 manualsite.py build
```

构建后刷新 `site/index.html` 即可看到清单、搜索、逐页阅读与**构建报告**（report.html / report.json）。`init` 命令仅保留兼容，不是必要前置；不指定 `site.json` 也会用默认配置构建。

> **已有一个单独的说明书目录、不想搬文件？** 用 `python3 manualsite.py build --manuals /原有说明书目录`。`--manuals` 会覆盖 `site.json` 中的 `manuals_dir`，本次构建会打印警示，但**不会改写**你的 `site.json`。

`manual.json`（可选）字段：

| 字段 | 怎么填 |
| --- | --- |
| `title` | 给人看的简明设备名称，如“空气净化器”，不要重复堆品牌、型号 |
| `category` | 设备类别；不填则「未分类」 |
| `brand` | 原件所示品牌；不确定就留空字符串 |
| `model` | 原件完整型号，保留大小写与连字符；不确定就留空字符串 |
| `aliases` | 确认过的俗称或其他型号写法；没有就写 `[]` |
| `tags` | 少量原件可确认的功能、用途或维护主题；没有就写 `[]` |

`manual.json` 是源资料，不是 Python 的构建产物。Python 的 `build` 读取它和原件，提取文字、生成 `site/index.html`、`site/manual/<id>/`（逐页网页、连续阅读 read.html、全文 fulltext.txt）、`catalog.json` 和搜索索引；这些输出无需自己编写。没有 `manual.json` 也能构建。

**PDF 文件名可以不规范。** 搜索优先使用设备信息和识别出的正文；如果缺少 PDF 提取／图片识别工具，只有设备信息能检索（搜索对元数据做 fallback），原件仍可打开。构建报告会完整列出缺工具原因、每页识别方式与未识别页，不会悄悄假装成功。

## PDF、照片与 OCR

| 输入 | 构建时使用的工具 | 缺少工具时 |
| --- | --- | --- |
| `.txt` / `.md` | Python 自带功能 | 可正常生成 |
| 文字型 PDF | `pdftotext`（Poppler） | 原件仍可下载，正文不可检索 |
| 扫描 PDF | `pdfinfo`、`pdftoppm`（Poppler）和 `tesseract` | 无文字的页会提示用户看原件 |
| JPG / PNG / WebP / TIFF | `tesseract` 及相应语言包 | 原图仍可阅读 |

每页记录识别方式 `direct`（直接提取）/ `ocr`（OCR 识别）/ `none`（未识别文字）。**未知 PDF 页数绝不虚构页面**：既无正文又无法用 `pdfinfo` 确认页数时，该本标记为「仅提供原件」且页数未知，并提示潜在缺页。每本说明书有状态：全部页面已提取文字 / 部分页面未提取文字 / 仅提供原件 / 处理失败；空白或无法识别的页不直接判失败。缓存带版本号，并在指纹中纳入 `pdfinfo`、`tesseract` 与语言包状态——装好工具或修正 `manual.json` 后缓存会自动失效重建，损坏的缓存也会重建。

## 静态内容与边界

- `site/index.html`：构建前的空站点说明资料目录；执行构建后变为设备清单、分类、浏览器端全文搜索和构建报告入口。
- `site/manual/<id>/index.html`：单本说明书资料和逐页链接。
- `site/manual/<id>/page-N.html`：可直接访问的逐页原文及原始文件定位。
- `site/manual/<id>/read.html` / `fulltext.txt`：按来源文件与原件页码分段的连续阅读与纯文本全文。
- `site/catalog.json`、`site/search.json`：供机器读取的构建产物，不是动态查询接口；浏览器还读取 `site/assets/search-index.js`，因此本地打开也能搜索。索引含全部识别出的正文，并对元数据（名称、品牌、型号、别名、标签）做 fallback，无正文的说明书也能按名称查到。小型家庭资料库适用，大型库需要分片索引。
- `site/report.html` / `report.json`：本次构建报告，含每本逐页状态、页序、完整告警、构建时间，以及与上次目录指纹相比的「新增 / 更新 / 移除」。

**不承诺任何 Agent 都能自动搜索全库。** 它必须先具备网页访问能力，并找到本站 URL；网站主页和逐页链接降低导航难度，但不能替代 Agent 的网页访问工具。浏览器内搜索依赖 JavaScript，纯网页读取工具未必会使用它。需要更强的“输入问题立刻返回相关页”的保证时，再考虑增加查询端点——当前不提供问答类服务。

公开部署前请自行检查转载许可、住址、序列号等个人信息。`site/` 默认包含原始 PDF 与图片；不要把私密资料放进将要公开发布的 `manuals/`。

## 原子发布与备份

构建在临时 staging 目录完成全部产物后，才把旧 `site/` **重命名**为带时间戳的备份（位于项目自己的 `.backups/`，每次构建一份、名称唯一），再把 staging 重命名为 `site/`。整个过程**不使用 `shutil.rmtree` 删除旧站或个人目录**：全局发布失败会回滚并保留旧站；单本说明书异常会被完整记录进报告、不影响其他说明书发布，也不会被静默吞掉。构建还会预检资料目录存在可读、不与输出/缓存/备份目录重叠，并拒绝穿透符号链接。

设计与维护约定见 [agent.md](agent.md)，当前完成情况见 [progress.md](progress.md)。
